When moving from table based authentication to another authentication system it maybe critical to remove the old authentication data from REDCap.

When table based authentication is used passwords are individually salted, hashed and stored in the REDCap database. When removing table based authentication, (example: switching from Table Based to OAuth), it may be good idea or even required to remove passwords from REDCap.

If a user login name is in the redcap_auth table, REDCap will try to authenticate the user as a table based user. Example: a username changes from "Bruce" to "Caitlyn" and the redcap_auth table still has "Bruce" and their password. They may be allowed to authenticate as the table based user "Bruce" but all of their projects and access control now belongs to Caitlyn. This may be very confusing if authentication is set to "Table based and Shibboleth" where Bruce is table based and Caitlyn is Shibboleth.

The SQL query below will set ALL passwords to NULL.

Once the SQL script runs, there is no way to recover passwords (other than backups).

Please use the SQL queries as your starting point. If you do not understand what the script will do, do not run it. There is another column, password_reset_key, which you may want to set to null as well. This script will work as long as REDCap keeps the password column NULLABLE.

Running the scripts below will remove ALL passwords, even yours. You may be locked out of the system.

Query 1

UPDATE `redcap_auth` set `password` = NULL

Query 2

UPDATE `redcap_auth` set `password_salt` = NULL

Query 3

UPDATE `redcap_auth_history` set `password` = NULL

For all Queries

SET SQL_SAFE_UPDATES = 0;
insert sql code here
SET SQL_SAFE_UPDATES = 1;
